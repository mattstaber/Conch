# Project layout

Conch has one set of Swift/C sources and two build entry points. Use
`Conch.xcodeproj` for the native macOS app, Icon Composer assets, debugging, and
hosted tests. `Package.swift` supports deterministic Swift tests and a fallback
command-line build; opening it in Xcode selects a different target from the native
app project. The project is generated by `scripts/generate-project.py` and committed
so it can be opened directly.

## Sources

| File under `Sources/` | Responsibility |
| --- | --- |
| `Conch/ConchApp.swift` | SwiftUI app entry, MenuBarExtra, mixer rows, settings, and login item control |
| `Conch/MixerModel.swift` | App discovery, row lifetime, route coordination, metering, and recovery |
| `Conch/MixerState.swift` | Volume/mute rules, launch identity, ownership path matching, and meter envelope |
| `Conch/ProcessResolver.swift` | Maps audio processes and helpers to running applications |
| `Conch/AudioHAL.swift` | Core Audio property access, observations, errors, and format validation |
| `Conch/AudioRoute.swift` | One app's process tap, private aggregate, callback setup, and teardown |
| `Conch/OutputVolume.swift` | Physical output volume/mute and hardware change observation |
| `Conch/VolumeSlider.swift` | Native NSSlider wrapper, volume buttons, and visual meter |
| `Realtime/Realtime.c` | Realtime sample gain, ramps, peak measurement, and callback health |
| `Realtime/include/Realtime.h` | Public C declarations |
| `Realtime/include/module.modulemap` | Makes the C interface importable from Swift |

## Tests and tools

`Tests/ConchTests/` contains state, ownership, hardware-volume, and opt-in live
routing tests. `Tests/realtime_tests.c` exercises the production callback with
synthetic buffers. `Tests/test_project_generation.py` verifies reproducible Xcode
project generation. `Tests/browser-tone.html` generates a local browser tone.

| Script under `scripts/` | Purpose |
| --- | --- |
| `build.sh` | Builds and signs the release app at `build/Conch.app` |
| `debug.sh` | Builds the native Debug app used by the Xcode scheme |
| `test.sh` | Runs Python, C sanitizer, and deterministic Swift tests |
| `live-test.sh` | Runs opt-in hosted audio tests; requires the documented QuickTime setup |
| `test-tone.py` | Creates `build/synthetic-tone.wav` for manual/live checks |
| `inspect-audio.sh`, `InspectAudio.swift` | Build/run a read-only audio metadata diagnostic |
| `generate-project.py` | Generates Xcode source membership, settings, and shared scheme |
| `format.sh` | Formats Swift sources using `.swift-format` |
| `icon.sh` | Exports the editable icon to PNG and fallback ICNS |
| `package.sh` | Packages the built release app and writes its checksum |

## Resources and documentation

`Resources/Info.plist` defines app identity, version, minimum OS, menu-bar behavior,
and the audio capture permission description. `Resources/AppIcon.icon/` is the
editable icon: `icon.json` composes `Assets/Channels.svg` and `Assets/Faders.svg`.
Xcode compiles its appearance variants. `AppIcon.png` is used by the README;
`AppIcon.icns` supports the fallback build. Separate appearance PNG exports are
not needed by the app.

`README.md` covers installation and use; `CONTRIBUTING.md` covers development;
`LICENSE` contains the MIT license. `docs/Architecture.md` describes implementation,
`Feasibility.md` preserves dated research, `Validation.md` distinguishes historical
results from outstanding checks, and `Releasing.md` covers distribution.
`.github/workflows/build.yml` defines CI and tagged releases. `.gitignore` excludes
local outputs, and `.swift-format` defines Swift formatting.

## Generated files and old builds

| Location | Purpose |
| --- | --- |
| `.build/Xcode/Build/Products/Debug/Conch.app` | Native Debug app, shared by Xcode and `debug.sh` |
| `.build/Xcode/Build/Products/Release/Conch.app` | Native Release build before release staging/signing |
| `.build/Xcode/` | Script-managed Xcode intermediates and logs; the IDE may also maintain its own DerivedData indexes |
| `.build/swiftpm/` | Swift package build/test products |
| `.build/cache/` | Compiler module cache |
| `.build/realtime-tests`, `.build/inspect-audio` | Compiled test/diagnostic tools |
| `build/` | Staged release app and generated manual-test/icon fixtures |
| `dist/` | Release ZIP and SHA-256 checksum |
| `.swiftpm/` | Local Swift package/Xcode integration state |
| `Conch.xcodeproj/project.xcworkspace/` and `xcuserdata/` | Xcode-created workspace/user state |
| `.git/` | Repository history and version-control metadata; preserve it |

The build products, caches, and local IDE state above are regenerable. Quit Conch
and stop builds before deleting build outputs. Do not delete sources, icon source,
project files, or Git history as part of clearing a stale app.

An already-built app does not update when source files change. Run the **Conch**
scheme from `Conch.xcodeproj`, or run `./scripts/debug.sh`, to rebuild Debug.
Quit any other running copy first. `build/Conch.app` is deliberately the release
app; `./scripts/build.sh` rebuilds it. Do not use old copies from `build/Xcode/`
or `.build/XcodeRelease/`; those former output locations are no longer used.
